# Permissions by operation

All live modes discover baseline API resource lists and create `authorization.k8s.io/v1` SelfSubjectAccessReviews. Ordinary generation needs only list access to `apps.openshift.io/v1` DeploymentConfigs in requested namespaces, plus API discovery. It does not GET namespace objects or cluster-version metadata. Reserved namespaces are filtered first. Offline input needs no cluster credentials.

Permission reviews specify the same resource API version as the operation: `v1` for baseline resources, `v2` for HPAs and the assessed admin-policy version when that optional API is used. This avoids relying on the empty/wildcard review-version default that changed in Kubernetes 1.28. An allowed review still does not bypass authorization or admission on the real request.

| Operation | Additional namespace permissions |
| --- | --- |
| Live plan | list core Services/RCs, apps Deployments/ReplicaSets/StatefulSets/DaemonSets, batch Jobs, autoscaling/v2 HPAs; get source DC and get known Services/HPAs during revalidation |
| Dry run and stage | get source DC, get/create Deployments, all live-plan revalidation permissions; discover ImageStreamTag API if image triggers are used |
| Cutover/recovery | get/update DCs and Deployments; list pods, RCs, ReplicaSets; get Services and Endpoints |
| Nonzero preflight/cutover | create Pods and ReplicaSets for dry run; list ResourceQuotas, LimitRanges and networking.k8s.io NetworkPolicies and policy/v1 PodDisruptionBudgets; create security.openshift.io/v1 PodSecurityPolicySubjectReviews; list quota.openshift.io/v1 AppliedClusterResourceQuotas; get mounted PVCs |
| Required-SCC mismatch during preflight/cutover | create namespaced authorization.k8s.io/v1 LocalSubjectAccessReviews when the subject review selects a different SCC from `openshift.io/required-scc`; no additional review permission for unpinned or matching templates |
| HPA cutover/recovery | get/delete/create HPAs, with original UID/version preconditions and retained snapshots |
| Integration harness only | CRUD test DCs, Deployments, Services, Routes, ImageStreams/Tags, HPAs and ResourceQuotas; list pods/RCs/RS; get the pre-labelled test namespace and read ClusterVersion/server metadata |

Create/update dry runs require the same create/update permission as a real request. Denied access reviews, unavailable APIs and real operation/admission failures all fail explicitly. Ordinary generation and planning remain namespace-scoped. Nonzero preflight/cutover additionally requires a read-only ClusterRole permitting **list nodes and list pods across namespaces**, so existing allocations cannot be mistaken for free node capacity. Mounted claims also require get access to their known PVs for node affinity. Cluster-version metadata reads remain qualification-only; cluster-admin, SCC changes and impersonation are not required. A missing inventory or dry-run permission blocks cutover before any HPA/source mutation. Rollback does not run this additional gate.

Nonzero preflight/cutover also discovers the optional `policy.networking.k8s.io` group. When its assessed `v1alpha1` AdminNetworkPolicy/BaselineAdminNetworkPolicy resources are served, it needs **cluster-scoped list access to those resources**. If policies exist, it additionally gets the **one target Namespace** to evaluate namespace selectors; a ClusterRole can restrict that get to the target namespace with `resourceNames`. Absent APIs need neither permission. Denied discovery/inventory, unassessed versions/resources/fields and changed source/destination Pod selection block retirement. The converter creates or changes no cluster network policy. Generation, planning and explicit recovery do not need these extra permissions.

SCC subject reviews may select a different policy even when the template requires a specific SCC. In that case the converter uses a namespace-scoped LocalSubjectAccessReview for the workload service account and groups, checking `use` of that exact SCC in the Pod namespace. A denied, uncertain or unavailable review blocks retirement. Once authorized, Pod dry run applies the required SCC's defaults to the original template; defaults returned for a different SCC are not replayed. The admitted SCC annotation and required-SCC annotation must both match the plan. The converter never grants SCC permissions itself. See [Kubernetes access-review semantics](https://kubernetes.io/docs/reference/access-authn-authz/authorization/#checking-api-access) and [OpenShift required-SCC behavior](https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html/authentication_and_authorization/managing-pod-security-policies).

LocalSubjectAccessReview checks the authorizer's decision; it does not inspect legacy direct SCC `users`/`groups` assignments. If a different SCC was selected and only a direct assignment permits the required policy, the converter conservatively refuses automatic retirement. An operator must review that assignment and provide an appropriate namespace RBAC grant or use a reviewed manual procedure. No cluster-wide SCC read permission is added to ordinary converter operations.

The core v1 Endpoints API is used as the 4.14 routing baseline. Later optional APIs are never assumed from a version number. If a required capability is absent, execution stops with a diagnostic. Deprecation warnings remain informational; permission, schema and admission errors are retained.

Do not grant namespace deletion, privileged SCCs or cluster-admin to the converter. Pause external reconcilers and scalers before cutover. The local plan lock coordinates one process only; it is not a cluster-wide lease.

The new-app integration runner additionally creates test namespaces, BuildConfigs/Builds, ImageStream imports and template-generated resources. The explicitly authorized regular-PVC case creates a 1Gi claim through an existing StorageClass and reads only its resulting PV metadata. These test-only permissions are not required by ordinary conversion; the regular-volume test uses default restricted pod admission without an extra SCC binding.

The singleton integration runner creates one namespaced `coordination.k8s.io/v1` Lease and a test account limited to get/update that named Lease. The permission runner creates short-lived TokenRequests for its explicit expiry case. These are harness-only dependencies; neither is required by the converter.
